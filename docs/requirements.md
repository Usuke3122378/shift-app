## 1. プロジェクト概要

### 背景
- 実際のバイト先がモデル。作者は**シフトに入るバイト側**。
- シフト作成者が、人が足りない日に毎月もう一度募集をかけていて大変そうだと感じたのがきっかけ。

### 現状のやり方（As-Is）
- バイトは約20人。それぞれが**個別のLINE**で勤務可能日をシフト作成者に送っている。
- シフト作成者がそれをGoogleスプレッドシートに手で入力して組んでいる。
- 必要な人数：**平日3人／土日祝4人**。各日**リーダーを1人**決める。
- バイトだけで足りない日は、**社員5人のうち1人**を入れる。
- シフト表のつくり（スクショ：`IMG_0619.JPG`、2026年10月分）
  - 行＝人（社員が上、その下にバイト。学生には「(学)」が付く）、列＝日付（1〜31日＋曜日）
  - 一番上に「充足可否」の行（○）、右端に「日数」（その人の出勤日数）の列
  - セルの書き方：**リーダー＝赤背景の「L」**、**フルタイム＝青背景の「F」**、**早番・遅番＝黒字**（スクショでは「前」「後」と書かれている）

### 困っていること
| 立場 | 困りごと |
|---|---|
| シフト作成者 | ① LINEで届いた全員の勤務可能日を1件ずつ手入力するのが手間 |
| シフト作成者 | ② 日ごとに人数が足りているか・多すぎるかが一目で分からない |
| シフト作成者 | ③ 足りない日を一覧で出せない（再募集のたびに自分で探している） |
| バイト | ④ 表が横長で、自分の行が見にくい |
| バイト | ⑤ 同じ日に誰が入っているかがすぐに分からない |

### 目的（To-Be）
- バイトが**自分で勤務可能日を入力**し、シフト作成者の手入力をなくす（①）
- 日ごとの人数を**自動で数えて**、足りない・多すぎるを色で分かるようにする（②）
- **足りない日の一覧**をワンタッチで出せるようにし、再募集をラクにする（③）
- バイトがスマホで**自分のシフトだけ**を見られ、**同じ日に入る人**もすぐ分かるようにする（④⑤）

### 使う人（ペルソナ）
| | シフト作成者 | バイト |
|---|---|---|
| 誰 | 社員のうちの1人 | 約20人（学生とフリーター） |
| 主な端末 | **パソコン** | **スマホ**（想定） |
| 今のやり方 | LINEで届いた勤務可能日をスプシに手入力 → 完成したシフト表を画像にしてLINEで送る | 個別のLINEで勤務可能日を送る → LINEで届いたシフト表の画像を見る |
| やりたいこと | 入力の手間を減らす／人数の過不足を一目で見る／足りない日を一覧にして再募集する | 自分のシフトだけをすぐ見る／同じ日に誰が入るかを知る |

### スケジュールのルール
- 勤務可能日の締め切り：**毎月20日までに翌月分**を提出

### 人数の数え方のルール
| 項目 | ルール |
|---|---|
| 必要な人数 | 平日3人／土日祝4人 |
| リーダー（L） | 各日1人。**人数に含める** |
| フルタイム（F） | 1人として数える |
| 早番・遅番（早／遅） | 交代で働くので**早1人＋遅1人で1人分**（1人あたり0.5人） |
| 社員 | バイトだけで足りない日に1人入れる。**人数に含める** |
| 足りない | 必要な人数より少ない |
| ちょうど | 必要な人数と同じ |
| 多すぎる | 平日4人以上／土日祝5人以上 |
| 表示 | L＝赤、F＝青、早・遅＝黒字（スクショの「前」「後」はアプリでは「早」「遅」と表示） |

### 全体の仕組み（2026-10-31 決定）
```
バイト（スマホのアプリ）              作成者（パソコンのGoogleスプレッドシート）
勤務可能日を入力 ──自動で反映──▶  可能日のセルが薄い黄色になる
                                     今までどおり L/F/早/遅 を打つ（自動で色が付く）
                                     人数の過不足は自動で色分け
自分のシフトを見る ◀──読み込み──  「公開する」にチェック
同じ日の人を見る

作成者（アプリの作成者画面）：足りない日の一覧＋再募集のLINE文面をコピー
```
- データの置き場所は **Googleスプレッドシート**（無料。作成者が慣れている）
- 作成者は**新しい画面を覚えなくていい**。シフト表の画像をLINEで送る手間もなくなる

### スコープ
- 含むもの（MVP）
  - バイト：名前を選ぶ／翌月の勤務可能日を入力・提出／自分のシフトを縦の一覧で見る／同じ日のメンバーを見る
  - スプシ：勤務可能日の自動反映（薄い黄色）／L/F/早/遅の自動色付け／人数の自動計算と過不足の色分け（祝日の自動判定を含む）／出勤日数の自動計算／公開チェック／翌月シートの自動作成
  - 作成者画面：足りない日の一覧／再募集用LINE文面のコピー
- 含まないもの（MVPではやらない）
  - ログイン（合言葉など）→ v1.0
  - 締め切り後の入力ロック、未提出者の一覧、各種警告 → v1.0
  - LINE通知、シフト案の自動作成、シフト交代、時間帯の希望 → v2.0
  - 給与計算・勤怠打刻（このアプリの目的外）

## 4. 非機能要件
> ✅ 2026-10-31 確定
- パフォーマンス：ページは3秒以内に表示。提出してからスプシに色が付くまで数秒以内
- 使いやすさ：バイト用はスマホ（横幅375px）で見やすいこと。ボタンは指で押しやすい大きさ（44px以上）。作成者用はパソコンで見やすいこと
- セキュリティ
  - スプシにつなぐための鍵（URLや秘密の値）は `.env.local` とVercelの環境変数にだけ置き、**GitHubには載せない**
  - 公開するスプシ・スクショ・記事には**本名を載せない**（ダミーの名簿を使う）
  - MVPはログインなし（名前を選ぶだけ）。なりすまし対策は v1.0 のパスキー（F-15）
  - 作成者用ページ（/admin）もMVPはログインなし。表示は「足りない日と人数」だけで名前は出さない（2026-10-31 決定）
  - Apps Script の窓口URLは、アプリのサーバー側（Route Handler）からだけ呼ぶ。ブラウザには出さない
- 可用性：Vercel の無料プランでの稼働で十分（お店の中だけで使うため）
- スケーラビリティ：利用者は約25人（社員5人＋バイト20人）。同時に使うのは多くて数人

### サイトマップ（アプリ）
```
トップ：名前を選ぶ（/）
├── 📱 バイト用（画面の下に2つのタブ）
│   ├── 自分のシフト（/me）
│   │   └── その日のメンバー（日付をタップすると下から出る小窓。別ページにはしない）
│   └── 勤務可能日を出す（/me/availability）
└── 💻 作成者用
    └── 足りない日・再募集（/admin）
        └── LINE文面のプレビューとコピー（同じページ内）

（v1.0 で追加）
├── ログイン・パスキー登録（/login）
└── 未提出の人（/admin の中に追加）
```
- 階層は最大3段（教材の目安「3層以内」を満たす）
- バイトの主な操作（シフトを見る・可能日を出す）は**開いてすぐ／タブ1回**で届く（目安「2クリック以内」を満たす）
- 名前を覚えている場合、トップを開くと自動で「自分のシフト」へ進む
